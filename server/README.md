# WorkBuddy Daily server extension

`dashboard_build.py` parses run logs into durable daily snapshots in `/var/lib/workbuddy-portal/metrics.sqlite`, then publishes masked admin dashboard JSON. `portal.py` provides invite-only, SMS-verified enrollment. It runs as an unprivileged user and cannot read the runner's existing token store. `import_enrollments.py` imports verified credentials from the private queue under the runner's lock.

The public entry is `/workbuddy/join/` on the same HTTPS host. The existing `/workbuddy/` admin dashboard remains behind Caddy basic authentication. New users need an invite code and a WorkBuddy SMS code. Returning users can log in by SMS. Each session only receives its own account records. Portal credential cookies are Secure, HttpOnly and SameSite=Strict. New credentials are written to mode 0600 queue files and imported into the runner's mode 0600 token store. The portal never exposes access or refresh tokens to the browser.

Deploy `portal.py`, `portal.html`, and `import_enrollments.py` to `/opt/workbuddy-portal`; install `workbuddy-portal.service`; replace `/usr/local/bin/workbuddy-dashboard-build` with `dashboard_build.py`; replace the admin `index.html` with `dashboard.html`; add a Caddy `handle_path /workbuddy/join/*` reverse proxy to `127.0.0.1:18886` before the protected `/workbuddy/*` handler. Set `WB_PORTAL_GROUP=workbuddyportal` for the dashboard builder, so the portal can read its per-account metrics. Run the importer every minute. Create invite codes with `sudo -u workbuddyportal python3 /opt/workbuddy-portal/portal.py invite N`; share `https://aicn.wiki/workbuddy/join/?invite=CODE` privately.

Only deploy the invite portal on an HTTPS origin. Do not run it as root or make the runner token store readable by the portal user. The SMS API uses normal TLS certificate verification.
