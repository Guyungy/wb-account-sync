# 从安全预览到桌面产品

## 产品方向与约束

目标不是“包装一个脚本”，而是提供可理解、可确认、可验证的本地数据迁移体验。

0.2.0a1 是范围收紧的 Alpha，不是现有所有资产同步能力的稳定替代品。保持 Python 核心与界面分离；不为产品化引入服务器、上传用户会话或强制注册账号。

完成度以可复现的验收证据判断，不按代码行数、功能数量或主观百分比判断。以下没有发布日期承诺。

## 已确认的多账号目标与当前差距

用户要求：所有明确参与的本人账号均保留历史，切换后可继续查看；同步通用偏好、规则与技能、连接器非敏感配置。不是把原账号数据迁走，也不是取消所有账号/企业的数据隔离。

当前工作区已有：`demo` 虚拟数据演练、`share-preview` 只读历史并集、`preferences-preview` 白名单差异预览。它们**不写回客户端**；原有单账号归属迁移不能作为此需求的执行器。

后续放行顺序：
1. **契约与权限**：确认受支持客户端版本、会话/正文/附件引用、账号与企业作用域，以及官方可用的导出/导入或共享能力。不能仅复制新会话 ID 后宣称内容可用。
2. **非破坏共享**：原始归属及源内容保持不变，设计显式参与名单、稳定来源映射、去重、双端修改冲突和删除传播策略；未知账号/企业不加入。
3. **配置分层**：设备共享设置不重复搬运；账号偏好字段级写回。规则/技能内容需审阅，不自动启用 hooks、权限或执行脚本。连接器非敏感配置与授权分离，目标自行授权。
4. **独立备份与恢复**：先在合成夹具中验证全部受影响文件/行的备份、回滚、崩溃和冲突保护，再在用户授权的可丢弃测试账号验收；不用日常历史做首次写入测试。
5. **切换验收**：A → B → A 都能在客户端打开历史及附件，修改/删除行为可解释；偏好生效且目标授权未被冒用。未通过前不提供常驻自动写回。

**拒绝复制：** 登录凭据、API 密钥、连接器主密钥/加密授权、支付绑定、渠道授权及企业权限。个人云记忆缓存是服务端管理内容，不写回冒充长期同步。

## P0：安全预览（当前交付）

**用户价值：** 看清将改哪些普通会话，再决定是否离线执行。

实现范围：同一 home、普通未删除会话、只改 `sessions.user_id`。

- 可安装 wheel、源码包、统一 CLI，运行无第三方依赖。
- 显式路径、完整 UUID、当前账号快照验证。
- stdout 默认只读计划；显式导出不覆盖已有文件。
- 数据库身份、schema、账号快照与逐行双向指纹核对。
- 跨状态目录的每 home 锁、SQL 原子事务、写前持久 journal。
- prepared/committed/restoring/restored 状态及保守撤销。
- 旧 live/sync/helper 等入口被拒绝，未知结构或权限不明拒绝写入。
- 合成测试与 CI 包构建，明确不涉及真实账号写入。

**放行条件：** 当前代码测试通过、wheel 干净安装通过、README 与能力一致，且发行版必须标 Alpha。

不处理自动化表、授权密钥、云端缓存、渠道绑定、跨目录文件及全库备份。核验不证明云端或客户端 UI 一致性。

## P1：恢复与可靠性工程

**用户价值：** 知道失败发生在哪里，知道能否安全重试。

工作包：
1. 扩展真正的子进程崩溃/强制退出测试，而不只模拟异常。
2. 多进程锁竞争、磁盘满、fsync 失败、计划损坏、操作系统权限变化。
3. 验证 SQLite WAL/rollback journal 各模式；不以删除 sidecar 来“修复”。
4. 建立受支持 schema、客户端版本、macOS 版本和芯片架构矩阵。
5. 记录人工恢复操作边界；恢复失败不得覆盖用户后续修改。
6. 独立代码审查、依赖与供应链审查、公开漏洞报告方式。

**放行条件：** 测试结果可定位到提交/发行包；所有阻塞级数据安全问题关闭；未知兼容组合明确拒绝。

## P2：可支持的 CLI Beta

**用户价值：** 安装、诊断、迁移、核验、恢复都能按文档完成，而非靠作者现场排障。

- 冻结命令、错误码、JSON schema、plan/journal 格式与升级策略。
- 在授权测试账号上完成真实 macOS 离线流程验收，不拿日常历史做故障实验。
- 明确区别“归属修改成功”“内容资产齐全”“界面可见”“云端一致”。
- 引入诊断包的显式导出与敏感字段预览；默认不上传。
- 明确用户数据归属/服务条款限制；只使用有授权的官方迁移或管理接口。
- 如果重新引入自动化迁移，必须独立走官方能力，不编辑私有自动化表。
- 完整备份与跨目录迁移分别立项，不复用普通行撤销冒充备份。

**放行条件：** 新用户安装与文档走查通过；实际恢复演练通过；发布支持矩阵和已知限制。

## P3：签名、公证的 macOS 桌面应用

**用户价值：** 不需要理解命令行就能完成“选择—检查—审阅—确认—核验”。

建议界面页面：
- 首页：当前工具版本、受支持范围、显式选择数据目录。
- 诊断：离线状态、schema、源/目标账号，阻塞原因可操作。
- 计划审阅：会话数量、冲突、未支持资产；敏感内容默认不展示。
- 执行与恢复：进度来自持久执行状态，不是模拟进度条。
- 结果：本地归属与 UI/云核验分别列出，不显示模糊的“全同步”。

技术选型保留决策门：优先评估原生 SwiftUI 壳 + 受限核心接口，对比轻量跨平台壳；任何方案必须复用同一安全核心、验证 IPC 请求和操作范围。签名、公证、权限提示、沙箱路径访问先做原型验证，再确定架构。

默认不加常驻服务。确需后台能力时单独设计权限、暂停/停止、升级与退出机制，不通过临时 helper 绕过系统拒绝。

**放行条件：** 真实用户走查通过；签名/公证产物可验证；卸载不删除个人数据；界面无法越过核心确认规则。

## 1.0 上线门槛

必须全部满足：
- P0–P3 有对应提交和可复現测试/评审记录。
- 明确支持矩阵，未知版本停止写入。
- 无未解决的发布阻塞级数据损坏/越权问题。
- 多阶段崩溃与恢复实测通过，后续用户修改不被覆盖。
- 安装、升级、卸载、隐私说明、漏洞反馈和支持渠道完整。
- 云端/授权能力有明确验证或明确不支持，绝不把文件复制等同于迁移完成。
- 发行文件校验、签名、来源可验证，长期灰度结论可审查。

## 明确未完成

图形界面、签名公证、PyPI、自动更新、完整备份、跨目录历史迁移、官方自动化迁移、凭据授权迁移、长期灰度评估，均不属于当前已交付能力。

分支中的安全 Alpha 不会替你部署/停用现有服务。已有旧进程可能继续运行，升级用户须先按 MIGRATION.md 停止旧服务。
